# O-Block game server (private online matches)

The server is **authoritative**: it alone decides health, damage, kills, respawns, the ZA bag and hold times,
match results, rewards (paid once per match), purchases/ownership, weapon unlocks, character choice, trunk loot,
item use, car-hop cash and developer actions. Game clients only send requests, and every request is checked against
`shared.json` (the same weapon table, progression numbers, 15 spawn points and map colliders the game uses).

## Run it

```
npm install
node server.js            # listens on PORT (default 8787)
```

Then in the game: **Private match · Online** → enter `ws://<server-address>:8787` → Connect → Create room (you get a
5-character code) or Join by code. The host picks the mode, bots on/off, bot count, difficulty and rules, then starts.

* A page served over **https** can only open **wss://** connections, so put the server behind TLS (any reverse proxy
  such as Caddy or nginx) when the game itself is on https.
* Some hosting sandboxes (including the Claude artifact viewer) block outside connections entirely; the lobby will say
  the connection failed. Run the game from your own web server to play online.

## Environment variables

| Variable | Meaning |
|---|---|
| `PORT` | Listening port (default 8787) |
| `DEV_TOKENS` | Comma-separated player tokens that may use developer commands. Every developer action is appended to `devlog.jsonl`. Leave empty in production. |
| `PROFILE_FILE` | Where profiles are saved (default `profiles.json`) |
| `ALLOW_TELEPORT` | `1` disables the movement speed check. **Automated tests only.** |

A player's token is generated by the game and stored in the browser (`localStorage` key `oblock_netToken`).

## What is validated

* **Shots**: equipped weapon matches and is unlocked for that profile's level; fire rate (with tolerance); the
  server counts every round and reload; the shot origin matches where the server has the shooter; each claimed hit:
  target alive, claimed distance matches the server positions, within weapon range, and line of sight against the map
  colliders. Damage comes from the server's weapon table (falloff, headshots, pellets, Double Damage, beer).
* **Movement**: speed-checked; impossible moves are corrected.
* **Purchases**: price, cash and not-already-owned. **Characters**: you can only play characters you own.
* **ZA**: pick-up distance, carrier, hold time (accumulated on the server), drop on death, respawn rule, winner.
* **Items**: trunk loot is rolled on the server (once per trunk per match, must be next to it); using an item checks
  the inventory. **Car hopping**: next to the car, cooldown per car.
* **Rewards**: computed on the server at the end of the match and recorded per match id so they can never be paid twice.

### Bots online
Bots need the 3D scene to think, so when the host turns bots on, **the host's browser runs the bot AI** and streams
bot positions. Bot health, damage, kills and respawns are still the server's, and every bot shot is validated exactly
like a player's. Landmines are disabled online (their damage is not server-validated yet).

## Tests

```
node test.js     # starts its own server on port 8899 with a throw-away profile file; 40 checks
```

## Keeping `shared.json` in sync
`shared.json` is exported from the game itself. After changing weapon stats, prices, unlock levels, rewards, spawn
points or the map, open the game in a browser, run `copy(exportSharedData())` in the developer console, and paste the
result into `server/shared.json`.

## Private match settings (v0.8.0)
The host edits these in the game's Private Match screen; the server cleans/clamps every value (`cleanSettings`) and
broadcasts the result, and refuses changes while a match is running.

| Setting | Values | Enforced by the server |
|---|---|---|
| name, maxPlayers | 24 chars · 2–8 | join refused when full |
| bots, difficulty | 0–12 · easy/normal/hard | host runs bot AI, server owns their health |
| time, kills | 0 = unlimited | match end |
| respawnOn, respawnDelay | on/off · 1–15 s | respawn timer; off = last one standing wins |
| hp, stamina | 50–200 · 50–200 % | max health (stamina is applied by each game) |
| weapons, unlocks, startWeapon | allowed list (Glock always) · levels/all · loadout/glock/random | start weapon, equip and shot validation |
| chars | allowed characters | others play as Masked Tracksuit |
| items, nic, abilities | on/off | search/use/ability requests refused when off |
| flash, mines | 0–3 | applied by each game at spawn |
| xpMul, cashMul | 1 / 0.5 / 0 (never above 1) | all match rewards |
| variant, classicHold, zaStart, respawn, resetAfter, spawns, botsCarry | Za / backpack-hold rules | bag spawn, reset, pickup, win |

Character abilities (Cop Double Damage, Jeff Triple Health) unlock only after a server-counted 10-kill streak, are
activated manually (one activation per unlock) and last until death.

## Developer sign-in (v0.9.0)
The developer menu has no button anywhere. Press **P ten times within ten seconds** to get the sign-in box.
Start the server with your password in its environment, e.g. `DEV_PASSWORD=yourpassword node server.js`; the
password is never stored in the game files. While connected (Private Match screen), signing in unlocks the menu and
the server accepts developer commands from that connection only. Wrong passwords: 3 tries, then an increasing wait.
Offline, only a local unpublished `js/dev.local.js` (from `dev-tools/`) can unlock it, on localhost only.
